## 2. 模块清单与职责

| 文件 | 职责 | 关键 API |
|---|---|---|
| `src/protocol.rs` | 报文组包（唯一持有字节布局知识的地方） | `packet(mode,bar,value,alarm,se)`、`init_packet(se)`、`bar_from_usage()` |
| `src/device.rs` | 设备发现/打开/写入封装 | `find(&api)`、`list_all(&api)`、`Display::write()` |
| `src/sensor/usage.rs` | CPU 占用率（sysinfo 差分） | `CpuUsage::sample()` |

| `src/runner.rs` | 主循环、降级、auto 轮换、重连 | `run(cfg)`、`display_loop()` |

| `src/main.rs` | CLI 与子命令分发 | `run` / `test` / `doctor` |

## 3. 关键设计决策（为什么这样写）

### 3.1 双层循环 = 重连即恢复

```
外层 loop（runner::run）
  refresh_devices() → find() 成功？
    ├─ 否：睡 3s 重试                      ← 覆盖：未上电/拔出/睡眠中断连
    └─ 是：发 init_packet（加载动画）→ 进入内层
         内层 loop（display_loop）         ← 逐帧采集→组包→写
           写失败（HidError）→ return Err → 回到外层重连
```

- **热插拔**、**睡眠唤醒**、**设备假死**统一收敛为"内层退出→外层重连"，不引入并发/回调复杂度；
- 唤醒后第一帧必然是加载动画，与官方行为一致。

### 3.2 看门狗驱动的刷新模型

实机验证（文档 02 §5）：停发报文数秒后屏幕回退。因此：

- `interval_ms` 在 `Config::load` 里钳位 **300–3000ms**（配置错也不会触发看门狗）；
- 刷新是**推模型**：每帧无条件重发当前状态（不做变化检测），保证任何丢帧最多 1 个周期自愈；
- 无"恢复/清屏"命令——停发即复位，程序退出天然干净。

### 3.3 温度降级链

```
probe_key() 按序尝试：TC0P → TC0C…TC7C → TCAD → Tp01 → TC0H
  ├─ 命中 → 记录键名，运行期逐帧采样
  └─ 全败 →
       启动告警（提示安装 VirtualSMC/SMCProcessor/SMCAMDProcessor）
       mode==Temp 时自动降级 Usage 模式           ← 功能不丢，只降级
运行期单帧失败 → 该帧兜底显示占用率；连续异常不放大（下一帧自愈）
```

- 数值健康检查在 `read_temp_c` 内（0–120℃ 越界即 Err）；
- AMD 平台 SMCAMDProcessor、Intel 平台 SMCProcessor 提供温度键——README 已写明依赖。

### 3.4 SE 变体：一个布尔贯穿全链

`find()` 读产品字符串：不以 `AK` 开头 → `Display.se = true`。
`packet(..., se)` 据此决定是否带 Report ID 16（SE 整体左移一位）。
**型号差异只存在于两个函数**，新增型号（如 AK400 PID 1）只需改 `device::find` 的匹配表。

### 3.5 跨平台条件编译（开发友好）

`sensor/temp.rs` 的 `smc` 模块用 `#[cfg(target_os = "macos")]` 分叉：

- **macOS**：IOKit FFI（`IOServiceOpen` + `IOConnectCallStructMethod`，selector 3/4 = 读键信息/读键值），零第三方依赖；
- **非 macOS**：占位实现返回 Err → `doctor`/`run` 在 Windows 上照常跑设备链路与占用率。

这使协议调试可在 Windows 上进行（本机已完成冒烟），温度逻辑留给 macOS 实测。

### 3.6 依赖极简

| crate | 用途 | 说明 |
|---|---|---|
| `hidapi 2.6` | HID 读写 | macOS 走 IOKit，与参考实现同款 |
| `clap 4` | CLI | derive 宏 |
| `sysinfo 0.30` | CPU 占用率 | 内部 host_processor_info |

不引入 serde/toml/async——配置是 5 行 key=value 解析，主循环是同步单线程；
**没有锁、没有通道、没有任务**，单帧耗时可忽略，故障面最小。

## 4. 数据流与时序

```
一帧（interval=1000ms）：
  cpu.sample()          ── sysinfo refresh_cpu（差分窗口=帧间隔，天然满足≥200ms）
  temp::read_temp_c(k)  ── 两次 IOConnectCallStructMethod（微秒级）
  组包 64B + hid write  ── 控制端点输出报告
  sleep(interval)
```

- auto 模式：`auto_switch_s`（默认 5s）轮换 温度↔占用率，切换无过渡帧（与官方一致）；
- 报警：温度 ≥ `alarm_c`（默认 90）→ D6=1，与显示模式独立（占用率模式下不评估）。

## 5. 配置模型

优先级：**CLI 参数 > `~/.config/ak500s-mac/config` > 默认值**

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | auto | auto（默认） / temp / usage |
| `unit` | c | c / f |
| `interval_ms` | 1000 | 300–3000（越界自动钳位） |
| `alarm_c` | 90 | 报警阈值 ℃ |
| `auto_switch_s` | 5 | auto 子模式停留秒数 |

## 6. 错误处理矩阵

| 故障 | 检测位置 | 行为 |
|---|---|---|
| hidapi 初始化失败 | `run`/`test`/`doctor` 入口 | 报错退出（环境级故障） |
| 设备不存在 | 外层循环 | 每 3s 重试，stderr 提示 |
| 单帧写失败 | 内层循环 | 退出内层 → 重连 → 重发初始化 |
| SMC 键全不可用 | 启动时 `probe_key` | 降级 usage 模式 + 安装提示 |
| 单帧温度越界 | `read_temp_c` | 该帧改显占用率 |
| 数值 >999 | `packet` | 钳位 999（屏幕仅 3 位） |
| 配置 interval 越界 | `Config::load` | 钳位 300–3000 |

## 8. 已知边界与后续演进

- **电源事件**：未显式监听 IOKit 电源通知（阶段 3 计划项）；当前依赖"写失败→重连"天然覆盖唤醒场景（唤醒后首帧写失败或屏幕看门狗复位，3s 内重连+动画恢复）。实测若恢复时间不达标再加 `IORegisterForSystemPower`。
- **多设备**：同 VID/PID 多台时 `find` 取第一台（现实单台场景足够；`list_all` 已备 doctor 扩展）。
- **风扇 PWM**：官方软件具备的 PWM 功能在 AK 系列数显上无屏幕侧协议（文档 02 §3），未实现且非本项目目标。
- **阶段 5 预留**：菜单栏 GUI（SwiftUI 薄壳）可通过 `doctor` 的 JSON 化输出 + `run --mode` 控制对接，命令面已收敛。

## 9. v0.2.0 扩展：通用 API 层（docs/09）

在上述架构上增量加入，未改变单写者模型：

```
外部程序 ──NDJSON──→ api.rs（UDS/TCP 监听线程）
                        │ 写 SharedState{external, mode_override}
                        ▼
        runner.display_loop 每帧：
          1) 外部帧有效 → 抢占渲染（TTL 到期自动清除）
          2) 否则内置模式（mode_override 可覆盖配置）
```

- `SharedHandle = Arc<Mutex<SharedState>>` 是全程序唯一的锁（API 线程写 / 主循环读，临界区为微秒级赋值）；
- 传输按平台分叉：macOS UDS `/tmp/ak500s.sock`（正式）、Windows TCP 127.0.0.1:5577（开发联调）——协议一致；
- 依赖增加 `serde/serde_json`（请求校验用），其余不变；
- CLI 新增 `show`/`rmode`/`ping`，与 API 等价（脚本接入零门槛）；
- 新增 6 项单测（请求校验、TTL 过期、release 语义），累计 12 项全过；
- 本机端到端实测通过（守护进程 + CLI 收发，含错误路径）。

## 10. v0.3.0 扩展：内置指标显示开关

三个入口控制 `show_temp` / `show_usage` 两个开关（优先级从高到低）：

| 入口 | 形式 | 生效时机 |
|---|---|---|
| API `config` 命令 | `{"cmd":"config","show_temp":false}` | 立即（不落盘，`release` 复位） |
| CLI 启动参数 | `run --no-temp` / `run --no-usage` | 进程生命周期 |
| 配置文件 | `show_temp=false` | 持久 |

**渲染决策**（display_loop 每帧）：

```
属意指标 = eff_mode 映射（temp/usage/auto 半场）
属意指标可用（开关开 + 采样成功）→ 渲染之
否则回落另一侧（若其开关开）
两侧皆不可 → 本帧停发：屏幕由看门狗回默认状态 = "纯 API 屏幕模式"
              （v0.3.1：不再发全 0 空帧，避免屏幕常显 0%）
```

- 纯 API 模式下外部 `show` 帧照常抢占渲染；
- 修复 v0.2.0 缺陷：外部帧渲染路径 `continue` 跳过 `sleep` 导致忙转（现统一走帧末 sleep）；
- `SharedState` 新增 `show_temp_override/show_usage_override`（与 mode_override 同锁同生命周期语义）；
- 配置加载重构出 `load_from(text, overrides)` 纯函数，配置单测不再依赖环境变量（并行测试安全）；
- 单测累计 17 项全过（新增 4 项配置解析 + 1 项 config 命令）。
