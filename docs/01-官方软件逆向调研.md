# 01 · 官方 Windows 软件逆向调研

> 调研对象：`E:\test_exe\DeepCool\`（官方 DeepCool Digital v1.2.12）及安装包。
> 调研日期：2026-09-07。分析产物保存在 `E:\ak500s_mac\analysis\`。

## 1. 官方软件整体架构

官方软件是 **Electron 应用**，分四层：

```
┌────────────────────────────────────────────────────────┐
│  DeepCool.exe（Electron 30 + Vue3 + Element Plus UI）   │
│  主进程代码被编译为 V8 字节码 out/main/index.jsc          │
├────────────────────────────────────────────────────────┤
│  命名管道 IPC                                            │
│  \\.\pipe\DeepCool_display_server   ← 显示控制指令        │
│  \\.\pipe\deepcool_sensor_data      ← 传感器数据          │
├────────────────────────────────────────────────────────┤
│  后台服务（resources/service/，C++ + spdlog + ZeroMQ）    │
│  deep_service.exe           设备通信 + 传感器汇聚         │
│  SensorBridgeServer.exe     HWiNFO 传感器桥接            │
│  DeepCoolDisplayService.exe IddCx 间接显示器驱动安装器     │
├────────────────────────────────────────────────────────┤
│  硬件访问                                                │
│  · node-hid 3.1 / usb 2.14（JS 层，AK 系列数显走 HID）     │
│  · HWiNFO64.dll 共享内存（温度/频率/占用率数据源）          │
│  · DeepCoolDisplayDriver.dll（UMDF/IddCx，仅 LCD 机箱屏用）│
└────────────────────────────────────────────────────────┘
```

### 关键取证事实

| 证据 | 来源 | 含义 |
|---|---|---|
| `package.json` 依赖 `node-hid`、`usb` | asar 解包 | 数显散热器走 **USB HID** |
| 日志「管道\\\\.\\pipe\\DeepCool_display_server 开启」「驱动初始化」 | `service/x64/logs-server/` | 服务负责实际设备通信 |
| 字符串 `Ak500sUsbService`、`initialization pid=,vid =`、`getDeviceByPidAndVid` | `index.jsc` 字符串池 | AK500S 有专属服务类，按 VID/PID 匹配 |
| 字符串 `USB\VID_%04X&PID_%04X`、`[READING_TEMP-%d]` | `deep_service.exe` | C++ 服务按 VID/PID 枚举，从 HWiNFO 读温度 |
| `DeepCoolDisplayDriver.inf`（UMDF + IddCx 扩展） | exe 内嵌 CAB 提取 | 虚拟显示器方案仅服务于**可传图片/视频的 LCD 设备**（CH690 等），与 AK500S 无关 |
| 渲染层设备路由 `/devices/akdigital/` | renderer JS 明文 | AK500S-DIGITAL 属于 "akdigital" 简单数显类 |

## 2. 官方软件对 AK500S 支持的功能范围

从 renderer 明文 JS 的设备能力矩阵看，`AK500S-DIGITAL` 支持：

- **CPU 温度显示**（℃/℉）——出现在 `cpuTFemperature` 列表
- **CPU 占用率显示**——出现在 `cpuUsage` 列表
- 状态条动画、超温报警（`setTempAlert`、`pwmEnable`、`manualMode`、`setPwm` 等主进程 API）
- **不支持**自定义图片/视频上传（那是 CH690/LT360 VISION 等 LCD 产品的功能）

> 结论：AK500S 屏幕是"三段式数显"（三位数字 + 状态条 + 单位图标），
> 需要复刻的功能面很窄，全量协议已在社区项目中文档化（见文档 02）。

## 3. 为什么官方不做 macOS 版

- Windows 版依赖 HWiNFO（闭源、Windows 专用）取传感器；
- LCD 产品线依赖 IddCx（Windows 间接显示框架）；
- 两者的 macOS 等价物（SMC / CoreDisplay 私有路径）官方无动力适配。
  这也解释了 macOS 侧必须自建传感器数据源（见文档 03）。

## 4. 逆向分析方法记录（供后续复查）

| 步骤 | 命令/工具 | 产出 |
|---|---|---|
| asar 解包 | `npx @electron/asar extract` | `analysis/asar_extracted/`（1.3GB） |
| 主进程分析 | 字符串池扫描 `index.jsc` | 设备服务类名、API 名、日志模板 |
| 服务分析 | `strings` 扫描 `deep_service.exe` 等 | 管道名、HWiNFO 索引格式、PDB 路径 |
| 驱动提取 | PE 内 `MSCF` 定位 + 7za 解 CAB | `analysis/cab_extracted/cab/`（IddCx 驱动三件套） |
| VID/PID | 字节码/二进制数值扫描未果 → 转社区开源项目交叉确认 | `analysis/find_vidpid.py` 等脚本 |

> 注：官方二进制内部未以明文表形式存储 VID/PID（运行时由 node-hid 枚举传入），
> 静态提取不可靠；实际数值以开源社区双仓库一致 + 实机 `hidutil` 验证为准。
