# 02 · AK500S DIGITAL 通信协议规格（核心文档）

> 来源：社区逆向项目双源交叉验证
> （`nortank/src/devices/ak_series.rs` + `device-list/` vs `ak500-digital-rs/src/main.rs`），
> 两独立实现在字节级完全一致。实机接入后需按 §7 做一次冒烟验证。

## 1. 物理与枚举层

| 项 | 值 |
|---|---|
| 接口 | 主板 9-pin USB 2.0 扩展口（散热器附带转接线） |
| 设备类型 | 标准 **USB HID**（无厂商内核驱动需求） |
| **VID** | `0x3633`（十进制 13875） |
| **PID（AK500S DIGITAL）** | `0x0004`（十进制 4） |
| 同 VID 其它 PID | 1=AK400，2=AK620，3=AK500，4=**AK500S**（及 SE 变体），5=CH560… |
| 传输方式 | HID **Output Report**（64 字节缓冲，实际有效 7 字节 + 填充） |

### DIGITAL 与 DIGITAL SE 的区别（重要）

两者 **PID 相同**，靠 HID 产品字符串区分：

- 产品字符串以 `AK` 开头（如 "AK500S DIGITAL"）→ 标准版，报文**含** Report ID；
- 不以 `AK` 开头（如 "A500S" 风格）→ **SE 变体**，报文**不含** Report ID，
  整个报文左移一字节（所有字段偏移 -1），且写入时需补足 64 字节。

## 2. 报文格式（标准版，7 有效字节）

```
字节  值域        含义
────────────────────────────────────────────────────────
D0    16 (0x10)  Report ID（固定）
D1    见模式表    显示模式 / 控制命令
D2    1–10       状态条档位（0 关闭；约=占用率/10 四舍五入）
D3    0–9        数字百位（BCD 拆分）
D4    0–9        数字十位
D5    0–9        数字个位
D6    0/1        超温报警标志（1 = 报警图标/闪烁）
D7–D63 0x00      填充（必须补零至 64 字节）
```

### D1 模式/命令字节

| 值 | 含义 |
|---|---|
| `170` (0xAA) | **初始化/加载动画**（连接后首先发送一次） |
| `19` (0x13) | 温度模式 · ℃ |
| `35` (0x23) | 温度模式 · ℉ |
| `76` (0x4C) | 占用率模式 · % |

> 数值为 0–999 的十进制按位拆分，例：温度 47℃ → D3=0, D4=4, D5=7。

## 3. 会话流程

```
1. 枚举设备        hidapi open(0x3633, 0x0004)
2. 读产品字符串     判断标准版 / SE 变体
3. 发送初始化       [16, 170, 0,0,0,0,0, 0×57]        ← 播放加载动画
4. 循环（周期 750ms–1000ms）：
     采集 CPU 温度/占用率
     组包 → 写入 64 字节 Output Report
     例（47℃，占用 62%，报警关）：
     [16, 19, 6, 0, 4, 7, 0, 0×57]
5. 退出（可选）     发送全零/加载动画报文复位
```

- 状态条：`usage < 15 → 1`，否则 `round(usage/10)`，>10 封顶为 10。
- 报警条件：温度 ≥ 90℃（194℉）时 D6=1（阈值可配置化）。
- 官方软件具备的 PWM/风扇手动曲线功能在 AK 系列数显上仅作用于接线策略，
  屏幕侧协议只有上述 7 字节，无隐藏功能面。

## 4. SE 变体报文（偏移 -1）

```
D0    模式字节（原 D1）
D1    状态条
D2–D4 三位数字
D5    报警
D6–63 填充
```

## 5. 定时与异常处理（含实机验证结论 ★）

> **★ 实机验证（2026-09-08）**：屏幕存在**看门狗超时**——停止发送报文后，
> 所显内容约几秒内自动消失/回退默认状态。因此：
> ① 驱动必须以 750ms–1s 周期**持续刷新**（非可选）；② 无需任何"恢复/清屏"命令，
> 停发即复位；③ 这正是官方软件与参考实现均采用无限循环的原因。

| 场景 | 处理 |
|---|---|
| 刷新周期 | 750ms（philling 版）或 1s（nortank 版）；低于 500ms 无收益；**必须 < 看门狗超时（实测约数秒）** |
| 写失败 | 重试 3 次 → 重新枚举设备（支持热插拔） |
| 设备拔出 | IOHIDManager/hidapi 设备移除回调 → 进入等待重连 |
| 睡眠/唤醒 | 监听 NSWorkspaceWillSleepNotification / IOKit 电源通知，唤醒后重新初始化（重发加载动画） |

## 6. macOS 侧访问权限

- USB HID 用户态读写：hidapi（IOHIDManager 后端）**无需 root、无需内核扩展、无需特殊 entitlement**；
- 注意：若打包为 App 并公证分发，HID 设备访问一般也不需要附加授权
  （非 HID 设备监控类的 `com.apple.usb` 私有接口才需要）。

## 7. 实机验证结果（✅ 已于 2026-09-08 全部通过）

| 项目 | 结果 |
|---|---|
| 设备枚举 | ✅ macOS 原生识别为 `AppleUserHIDDevice`，无需任何驱动 |
| VID / PID | ✅ `0x3633 / 0x0004`（与文档一致） |
| Manufacturer / Product | ✅ `DeepCool / AK500S-DIGITAL` → 以 "AK" 开头，**标准版（非 SE）** |
| usagePage / usage | ✅ `0x00FF / 0x0001`（厂商自定义页；hidapi 可直接 open，无需过滤） |
| interface / 传输 | ✅ interface 0，USB 传输 |
| 序列号 | `1FEC105A4C38`（已登记） |
| 测试 1 加载动画（16,170,…） | ✅ 屏幕播放动画 |
| 测试 2 温度 47℃（16,19,5,0,4,7,0,…） | ✅ 显示 47 |
| 测试 3 占用 62%（16,76,…） | ✅ 显示 62 + 状态条 |
| 测试 4 报警位（16,19,10,0,9,5,1,…） | ✅ 报警生效 |
| 行为补充 | 停发报文数秒后内容自动消失（看门狗），见 §5 |

**结论：协议规格无需修订，阶段 0 通过，可进入阶段 1 编码。**
