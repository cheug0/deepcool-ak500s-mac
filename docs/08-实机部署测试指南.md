# 08 · 实机部署测试指南（黑苹果）

> 对应实现：`E:\ak500s_mac\ak500s-mac\`（Rust 工程）。
> 全程在黑苹果的「终端」执行。阶段 0 已验证设备枚举与协议（文档 06），
> 本指南完成 部署 → 自检 → 链路测试 → 常驻运行 → 验收。

---

## 1. 前置检查（5 分钟）

| # | 检查 | 命令/方法 | 通过标准 |
|---|---|---|---|
| 1.1 | macOS 版本 | `sw_vers -productVersion` | 10.13+（IOKit HID 用户态访问均可） |
| 1.2 | CPU 平台 | `uname -m` / `sysctl machdep.cpu.brand_string` | 记录 x86_64 还是 arm64，决定是否做通用二进制 |
| 1.3 | 设备在线 | `hidutil list \| grep -i 3633` | 出现 `0x3633 0x4 … AK500S-DIGITAL`（阶段 0 已验） |
| 1.4 | 磁盘/网络 | 能访问 GitHub（rustup 需要联网） | — |

> 若 1.3 无输出：先按文档 06 §七 排查 USB 链路，再继续。

## 2. 部署工程（2 分钟）

把 Windows 侧 `E:\ak500s_mac\ak500s-mac\` 整个目录拷到 Mac
（U 盘/网盘/`scp` 均可；**无需**拷 `target/`，那是 Windows 构建产物）：

```bash
# 假设放到用户目录
mv ~/Downloads/ak500s-mac ~/ak500s-mac && cd ~/ak500s-mac
```

## 3. 安装编译链（首次约 10 分钟）

```bash
# 3.1 Xcode 命令行工具（编译 hidapi 的 C 源码需要）
xcode-select --install        # 弹窗确认；已装会提示，跳过即可

# 3.2 Rust（stable 默认宿主即可）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
source "$HOME/.cargo/env"
rustc --version               # 确认可用
```

## 4. 构建

```bash
cd ~/ak500s-mac
cargo build --release 2>&1 | tail -3
# 预期：Finished `release` profile ...，产物在 target/release/ak500s-mac
```

（可选）通用二进制，Intel/ARM 黑苹果通用：

```bash
rustup target add x86_64-apple-darwin aarch64-apple-darwin
cargo build --release --target x86_64-apple-darwin
cargo build --release --target aarch64-apple-darwin
lipo -create target/x86_64-apple-darwin/release/ak500s-mac \
           target/aarch64-apple-darwin/release/ak500s-mac \
           -out ak500s && file ak500s   # 应显示 two architectures
```

## 4A. 版本升级（已部署过旧版本的机器）

> 适用：之前按本文档部署过、现在要更新到新版本。全新部署跳过本节。

```bash
cd ~/ak500s-mac                     # 当初部署工程的目录
git pull                             # zip 拷贝部署的：重新覆盖一次文件

# 停止旧进程（LaunchAgent 自启动的先卸载；前台运行的 Ctrl+C）
./scripts/uninstall.sh
pkill -f "ak500s-mac run" 2>/dev/null

cargo build --release
./target/release/ak500s-mac doctor   # 自检通过后再恢复常驻
./target/release/ak500s-mac run      # 前台观察确认正常
./scripts/install.sh                 # 需要开机自启的重新装回
```

- 配置文件（`~/.config/ak500s-mac/config`）与日志目录升级后保持不变；
- 版本行为差异见 `ak500s-mac/README.md` 的「版本历史」表；
- 升级后首次运行建议核对启动日志：模式应为 `auto`（0.3.2 起），
  温度键命中行 `温度键: TCxx（℃）` 正常出现。

## 5. 首次自检：`doctor`（3 分钟，核心步骤）

```bash
./target/release/ak500s-mac doctor
```

**逐段核对输出：**

| 输出段 | 预期（Intel 黑苹果示例） | 判读 |
|---|---|---|
| 设备枚举 | `[OK] 找到 1 台 AK500S:` + `product="AK500S-DIGITAL" serial="1FEC105A4C38" usagePage=0xff usage=0x1` | product 以 AK 开头 → 标准版（报文带 Report ID 16）✅ |
| 变体判定 | `标准版（报文带 Report ID 16）` | 与阶段 0 一致 ✅ |
| SMC 探测 | `[OK] TC0P = 45.3℃ ← 将使用此键` | **任一键命中即通过** |
| 占用率采样 | `[OK] 当前占用率 xx.x%` | 数值与活动监视器同量级 ✅ |
| 结尾 | `== 自检通过，可 ak500s run ==` | 退出码 0 |

**两种常见非通过情形：**

1. `[FAIL] 未发现 3633:0004 设备` → USB 链路问题，按文档 06 §七排查；
2. `[FAIL] 无可用温度键` → SMC kext 缺失：
   - **Intel**：OpenCore 加 `VirtualSMC.kext` + `SMCProcessor.kext`（重启后重试）；
   - **AMD**：加 `VirtualSMC.kext` + [SMCAMDProcessor.kext](https://github.com/trulysinclair/SMCAMDProcessor)；
   - 短期可忽略：程序会自动降级为占用率模式。

## 6. 链路测试：`test`（2 分钟）

```bash
# 屏幕显示 47，状态条半格，每秒 1 帧共 5 帧
./target/release/ak500s-mac test --mode temp --value 47 --bar 5

# 占用率模式 88 + 满格
./target/release/ak500s-mac test --mode usage --value 88 --bar 10

# 报警位验证（显示 95 + 报警图标）
./target/release/ak500s-mac test --mode temp --value 95 --bar 10 --alarm
```

通过标准：屏幕对应显示正确；**停止发送后几秒消失属正常**（固件看门狗，勿视为故障）。

## 7. 常驻运行：`run`（5 分钟观察）

```bash
# 前台运行观察（默认 auto：温度/占用率 5s 轮换，1s 刷新）
./target/release/ak500s-mac run

# 另开终端窗口造压力验证动态性（注意：一个 yes 只打满一个核心，
# N 线程 CPU 上全局占用率仅约 100/N%，必须按线程数启动多个）：
for i in $(seq $(sysctl -n hw.logicalcpu)); do yes > /dev/null & done
# 全核满载 → 占用率应到 99–100%、状态条满格；auto 模式可顺带观察温度爬升
killall yes              # 结束负载

# 常用变体：
./target/release/ak500s-mac run --mode usage          # 仅占用率
./target/release/ak500s-mac run --mode auto           # 温度/占用率 5s 轮换（--auto-switch-s 可调）
./target/release/ak500s-mac run --fahrenheit          # 华氏度
./target/release/ak500s-mac run --alarm_c 85          # 自定义报警阈值
```

观察清单：温度趋势与 Stats/活动监视器一致；状态条随负载变化；`Ctrl+C` 停止后屏幕数秒内回默认（正常）。

## 8. 开机自启动（LaunchAgent）

```bash
./scripts/install.sh      # 自动定位 release 产物，安装并立即启动
launchctl list | grep ak500s   # 有输出即已托管
tail -f ~/Library/Logs/ak500s-mac/err.log   # 看运行日志（Ctrl+C 退出查看）
```

重启一次 Mac 验证登录后屏幕自动点亮。

卸载：

```bash
./scripts/uninstall.sh    # 停止并移除（日志保留）
```

## 9. 验收清单（对应文档 04 里程碑）

| # | 验收项 | 方法 | 通过标准 |
|---|---|---|---|
| 9.1 | 登录自启 | 重启后计时 | 登录后 **3 秒内**屏幕开始显示 |
| 9.2 | 数值正确性 | 全核拷机（按 `sysctl -n hw.logicalcpu` 启动多个 `yes`）+ 降温（空闲） | 占用率/温度与 Stats 趋势一致（±3%） |
| 9.3 | 报警 | `run --alarm_c 40`（人为低阈值） | 温度超 40℃ 时屏幕报警位生效 |
| 9.4 | 热插拔 | 运行中拔掉 9-pin 再插回 | **10 秒内自动恢复显示**，程序不退出 |
| 9.5 | 睡眠唤醒 | 合盖/手动睡眠 30s 后唤醒 | **10 秒内恢复**（含加载动画） |
| 9.6 | 稳定性 | 常驻挂机 ≥24h | 屏幕持续刷新；`ps -o rss= -p $(pgrep ak500s-mac)` 内存无持续增长 |

> 9.1–9.5 全过即可视为交付；9.6 不达标时检查日志（`~/Library/Logs/ak500s-mac/`）定位问题。

## 10. 故障速查

| 症状 | 原因 | 处置 |
|---|---|---|
| doctor 找不到设备 | USB 端口映射把该口移除 / 针脚接触不良 | 换 9-pin 针脚；重做 USB 定制；冷启动 |
| doctor 找不到设备（仅 run 时） | LaunchAgent 环境的 HID 权限差异 | 先看 err.log；必要时改用 Homebrew 版路径并在 plist 里写绝对路径（install.sh 已处理） |
| 温度键全不可用（Intel） | 缺 SMCProcessor | OC 添加 kext → 重建缓存 → 重启 |
| 温度键全不可用（AMD） | 缺 SMCAMDProcessor | 同上；项目自动降级占用率模式可用 |
| 温度显示 0 或异常值 | 键探测命中了不合适的键 | 依据 doctor 输出调整键探测链顺序 |
| 屏幕显示数秒后消失 | 看门狗（正常机制） | 确认 `ak500s run` 在运行、interval ≤3000ms |
| 屏幕数值与系统监控差很多 | 温度键口径差异（如 Tctl vs 包温） | 属正常；可指定换键（改探测链顺序） |
| 唤醒后长时间不恢复 | 个别主板 USB 唤醒时序 | 阶段 3 加电源监听；临时方案：interval 调小至 750ms |

## 11. 回退方案

- 停止服务：`./scripts/uninstall.sh`（或 `launchctl bootout gui/$(id -u)/com.ak500s.mac`）；
- 屏幕即回默认状态（无固件残留、无刷写风险）；
- Windows 双系统不受任何影响（官方软件独立工作）。
